# EduPro Learner Intelligence Dashboard — Delivery Phases

## Phase 1 — Foundation and data readiness

**Goal:** establish a trustworthy joined analytic dataset.

- Confirm file locations and input format.
- Create the project structure and dependency list.
- Implement loaders for Users, Courses, and Transactions.
- Validate schemas, ID uniqueness, data types, and foreign-key relationships.
- Clean categorical values and derive the ordered age groups.
- Produce a data-quality summary and unit tests for transformations.

**Exit criteria:** a reproducible analytic dataset joins valid users, courses, and enrollments; data issues are reported.

## Phase 2 — Core dashboard and KPIs

**Goal:** let stakeholders understand platform reach and course demand.

- Build Streamlit layout, header, sidebar, and data-status panel.
- Add global filters for age group, gender, category, and level.
- Implement KPI cards: total enrollments, active learners, leading category, and leading level.
- Add age distribution, gender participation, age-wise enrollment, and category popularity charts.
- Test that filters change every KPI and visual consistently.

**Exit criteria:** the first four analytical questions can be answered interactively with accurate filter-aware metrics.

## Phase 3 — Preference and behavioral analysis

**Goal:** expose meaningful demographic patterns without overclaiming.

- Add age-group × course-category heatmap.
- Add gender × course-level comparison.
- Add course type and level distribution views.
- Calculate average courses per learner and enrollment concentration among active users.
- Add short, data-backed insight statements and clear empty-state behavior.

**Exit criteria:** all core analytical questions and listed behavioral insights are represented in the dashboard.

## Phase 4 — Validation, reporting, and release

**Goal:** deliver a polished, trustworthy submission.

- Review computations against sample/manual aggregates.
- Test invalid-file, missing-data, and no-filter-result states.
- Verify accessibility, labels, responsive layout, and visual consistency.
- Write the EDA/research report with insights and recommendations.
- Write the executive summary for government stakeholders.
- Document setup, data assumptions, and known limitations in the README.

**Exit criteria:** dashboard, research report, and executive summary are ready for submission.

## Coding-time memory policy

Create `Memory.md` only when Phase 1 implementation starts. Update it after each meaningful coding session with completed work, active decisions, changed files, verification, known issues, and the next smallest task. Do not use it to duplicate the PRD or source code.
